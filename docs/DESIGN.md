# Design

Leesh Loop의 UI는 사용자가 중요한 정보와 행동을 자연스럽게 발견하고, 현재 상황을 이해하며, 작업을 이어갈 수 있게 해야 한다.

디자인은 화면을 정돈하는 일이 아니라 정보와 행동의 의미와 우선순위를 드러내는 일이다.

## Reflect the user's work

좋은 화면 구조는 내부 구현이나 데이터 구조보다 사용자의 실제 작업 구조를 반영한다.

사용자가 어떤 순서로 상황을 이해하고 결정하고 행동하는지가 화면의 정보 순서와 위계에 드러나야 한다.

관련된 기능이 많다는 이유만으로 모든 기능을 같은 중요도로 보여주지 않는다.

## Make importance visible

중요한 정보와 행동은 별도의 탐색 없이 발견할 수 있어야 한다.

좋은 hierarchy는 typography, spacing, sizing, alignment, grouping, boundaries, placement와 같은 구조 자체에서 드러난다.

색상이나 장식은 그 hierarchy를 강화할 수 있지만 대신해서는 안 된다.

색상을 제거하더라도 무엇이 중요한지, 무엇이 primary action인지, 정보들이 어떤 관계에 있는지 이해할 수 있는 상태를 좋은 기본 구조로 본다.

## Protect attention

한 화면에 많은 정보를 담는 것보다 사용자가 지금 주의를 기울여야 할 대상을 명확하게 만드는 것을 우선한다.

정돈된 화면이라도 중요한 항목을 찾기 위해 반복적으로 탐색하거나 스크롤해야 한다면 충분히 좋은 디자인으로 보지 않는다.

Primary task와 직접 관련된 정보는 중심에 두고, 상세 정보와 보조 navigation은 접근 가능하되 현재 작업과 경쟁하지 않게 한다.

## Support continuation

좋은 UI는 현재 상태를 보여주는 것에서 끝나지 않고 다음 행동으로 이어지게 한다.

사용자는 성공, 실패, 진행 중인 상태를 이해할 수 있어야 하며, 그 결과 무엇을 할 수 있는지도 자연스럽게 파악할 수 있어야 한다.

시스템 내부 표현보다 사용자가 판단하고 행동하는 데 필요한 의미를 우선한다.

## Preserve meaning across presentation

화면 크기나 배치가 달라져도 정보의 의미와 작업의 우선순위는 유지되어야 한다.

Responsive design은 서로 다른 화면마다 다른 정보 구조를 만드는 것이 아니라, 제한된 공간에서도 동일한 의미와 행동 관계를 보존하는 문제로 본다.

## Respect authority

UI는 이미 다른 시스템이 소유하는 의미를 임의로 다시 정의하지 않는다.

State, validation, identity, lifecycle 또는 canonical data에 기존 authority가 있다면 UI는 그 의미를 표현하고 연결한다.

사용자에게 더 이해하기 쉬운 표현을 제공할 수는 있지만, 이를 위해 별도의 사실이나 정책을 만들어내지 않는다.

## Judge design by use

디자인의 완성도는 장식의 양이나 정돈된 인상만으로 판단하지 않는다.

다음이 자연스럽게 성립하는지를 중심으로 본다.

- 중요한 것이 먼저 발견되는가

- 실제 작업 순서와 화면의 위계가 맞는가

- primary와 secondary가 명확한가

- 사용자가 현재 상태와 다음 행동을 이해할 수 있는가

- 정보량이 늘어나도 중요한 대상을 찾기 쉬운가

- 표현 방식이나 화면 크기가 달라져도 의미가 유지되는가

- 색상에 의존하지 않아도 구조와 우선순위가 성립하는가

좋은 디자인은 사용자가 화면의 구조를 해석하는 데 쓰는 노력을 줄이고, 실제 작업에 더 직접적으로 집중할 수 있게 한다.
